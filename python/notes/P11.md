## CLI 错误边界与 sys.exit 问答

用户追问 CLI 层捕获文件/编码失败的含义，以及为什么不能在 main 中直接 sys.exit(数字)。教师说明：CLI 层就是 app.py 的入口编排；文件层让异常传播，入口层决定面向用户的诊断与退出码，二者不冲突。补充了 try/except 的示意调用链与 main 返回码的例子。

纠正上一轮可能造成的误解：main 内直接 sys.exit 完全合法，返回码加入口 sys.exit(main()) 是可测试性建议，不是必须修改的验收条件。两者均可，只要任务失败时提供 stderr 诊断、退出1且不打印成功摘要。main 返回1本身不自动改变进程退出码；sys.exit 抛 SystemExit，正常退出会执行 finally/with 清理。

## 错题与后续回访

- ID 不等于文件行号，空白行也占行号。
- f-string 嵌套引号与解释器版本有关，应使用课程环境。
- errors 的元组契约、read_records 的带行号返回结构不能混用。
- or 短路不能保护分支里的不安全字段访问。
- 文件层传播异常，CLI 层负责诊断和退出；SystemExit 与函数返回不同。
- 比较表达式不是断言，预期异常未发生也必须验证失败。
- sort 原地修改返回 None，sorted 返回新列表，key 必须按关键字传入。
- UnicodeDecodeError 与 UnicodeEncodeError 均属于 UnicodeError。
