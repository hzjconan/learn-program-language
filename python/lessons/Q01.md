## 1. PyTorch 与一次更新

PyTorch 提供 Tensor 数值计算、模型与参数组织、自动求导。模型参数如权重和偏置在训练中更新；学习率、batch size、轮数是超参数。

```python
import torch
from torch import nn

x = torch.tensor([[1.0], [2.0], [3.0]])
y = torch.tensor([[3.0], [5.0], [7.0]])
model = nn.Linear(1, 1)
loss_fn = nn.MSELoss()
optimizer = torch.optim.SGD(model.parameters(), lr=0.01)

model.train()
for step in range(100):
    optimizer.zero_grad()
    prediction = model(x)
    loss = loss_fn(prediction, y)
    loss.backward()
    optimizer.step()
```

x 的 shape 为 [3, 1]：3 个样本，每个 1 个特征。Linear(1,1) 计算 wx+b。MSE 是预测误差平方的平均。model.parameters() 提供参数，SGD 根据梯度更新它们；简单更新为旧参数减学习率乘梯度。

zero_grad 清梯度，不清参数；backward 计算并累加梯度；step 实际更新参数。本例更新 100 次，每次使用全部 3 个样本。model.train() 切换模式，不自动执行训练。

## 2. Batch、step、epoch

batch 是一批样本；此处 step 指一次优化器更新；epoch 是完整遍历一轮训练集。10000 条、batch=100、5 轮，每批更新一次，共 500 次更新。梯度累积时批次数不等于更新次数。

```python
from torch.utils.data import TensorDataset, DataLoader

dataset = TensorDataset(x, y)
loader = DataLoader(dataset, batch_size=2, shuffle=True)
for epoch in range(5):
    model.train()
    for batch_x, batch_y in loader:
        optimizer.zero_grad()
        prediction = model(batch_x)
        loss = loss_fn(prediction, batch_y)
        loss.backward()
        optimizer.step()
```

TensorDataset 配对输入答案；DataLoader 分批，shuffle 不破坏配对。3 条样本默认每轮两批（2 条和 1 条）。跨批、跨轮保留参数。

## 3. 验证与最终评测

训练集用于更新参数；验证集用于选检查点、调超参数和观察过拟合；独立测试集在方案确定后评估最终表现。清洗去重，防止重复或高度相似数据跨集合泄漏；反复按测试集调参会使它间接参与模型选择。

```python
model.eval()
with torch.no_grad():
    prediction = model(x_valid)
    val_loss = loss_fn(prediction, y_valid)
```

eval 切换特定层行为（如 Dropout、BatchNorm），不自动评测、不禁用梯度、不禁止参数更新。no_grad 禁用该上下文中的梯度记录；正常验证流程不做 backward/step。no_grad 不会清除已有梯度；若已有梯度，执行 step 仍可能更新参数。线性层本身在两种模式下行为相同。

训练 loss 下降而验证 loss 持续上升，通常提示过拟合；数据不足或过于相似可能是原因，不能凭曲线确定根因。可选验证指标最佳检查点、早停，并实验比较数据与正则化等调整。loss 没有跨任务通用合格阈值。

任务指标需匹配目标：回归可用 MAE，分类用 accuracy/precision/recall/F1，检索用 Recall@k，生成任务检查引用、内容、格式和拒答等。类别不平衡时 accuracy 可能掩盖少数类全漏的问题。

法律助手例：loss 1.2→0.6，格式合规率 70%→95%，引用准确率 60%→45%；格式改善不能证明任务成功。引用需定义清楚，条款定位与引用原文准确性分别衡量。与未微调基座比较，并做真实生成评测。

## 4. 映射到语言模型微调

对话→chat template→tokenizer/token ID→分批、padding、mask→前向→token loss→反向→更新。语言模型通常预测下一个 token；助手部分 loss mask 决定哪些目标位置参与训练。

全参数微调更新基座参数；LoRA 冻结基座，更新适配参数，仍有前向和反向。tu-assistant 使用 MLX-LM，概念可对应，API 不相同。

teacher forcing 使用标准答案前文预测后续 token；生成时接着模型自己的输出，错误可能累积。因此低验证 loss 不能代替生成评测。

推理保存模型权重或适配器，以及匹配的配置、tokenizer、基座版本等。完整续训还要考虑优化器、调度器、步数等状态。正常推理不更新参数。

## 5. 补充：checkpoint 保存与恢复

checkpoint 是某个训练时刻的存档，用于中断恢复、选取最佳模型和复现实验。state_dict 是状态字典，模型中包含参数与持久缓冲区，不包含模型类定义。

推理权重保存与加载（沿用 CPU 线性模型）：

```python
torch.save(model.state_dict(), "weights.pt")
restored = nn.Linear(1, 1)
state = torch.load("weights.pt", map_location="cpu", weights_only=True)
restored.load_state_dict(state)
restored.eval()
with torch.no_grad():
    prediction = restored(x)
```

先创建匹配结构，再加载数值。文件后缀 .pt/.pth 是惯例，不决定是否包含完整训练状态。

训练恢复示例（epoch 为从零开始、刚完成的轮次；示例换用有历史状态的 Adam）：

```python
torch.save({
    "epoch": epoch,
    "model": model.state_dict(),
    "optimizer": optimizer.state_dict(),
}, "last.pt")

checkpoint = torch.load("last.pt", map_location="cpu", weights_only=True)
model = nn.Linear(1, 1)
optimizer = torch.optim.Adam(model.parameters(), lr=0.001)
# 保存端也必须采用与恢复端匹配的 Adam 和参数组织。
model.load_state_dict(checkpoint["model"])
optimizer.load_state_dict(checkpoint["optimizer"])
start_epoch = checkpoint["epoch"] + 1
model.train()
```

仅载权重也能继续训练，但优化器历史可能重置。Adam 保存的一阶矩、二阶矩估计及更新计数不等于参数当前的 .grad。通常在一次参数更新完成的边界保存时，无需保存这一批的原始梯度，下一批重新前向/反向即可；若在梯度累积中途精确恢复，则还需处理尚未用于更新的累计梯度。完整恢复还按实际配置保存调度器、混合精度 scaler、随机状态、采样/数据位置等；epoch 末保存较容易恢复。上述片段不保证逐位复现。

last.pt 保存最近进度，best.pt 按预先选定的验证指标保存最佳权重。以 val_loss 为准时，只有更低才覆盖 best；不根据最终测试集反复挑模型。内存中 best_state = model.state_dict() 不是独立快照，应立即保存到磁盘或 deepcopy 状态。

LoRA adapter 通常不含基座和完整优化器状态，要记录对应基座、配置和 tokenizer。保存磁盘 checkpoint 与 gradient checkpointing（重算激活换内存）是两种不同机制。

参考：[PyTorch 保存与加载](https://docs.pytorch.org/tutorials/beginner/saving_loading_models.html)。
