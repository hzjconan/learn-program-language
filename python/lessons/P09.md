## 1. 导入模块与导入名字

一个 `.py` 文件可以作为模块导入。以普通方式首次导入某个模块名时，Python 执行模块的顶层代码，并缓存模块对象。同一进程里再次按同一个名字导入时，会复用这个对象。

| 写法 | 在当前模块中创建的绑定 |
|---|---|
| `import settings` | `settings` 指向模块对象，可以用 `settings.timeout` 读取属性 |
| `from settings import timeout` | `timeout` 指向导入时该属性所指向的对象 |

结合 P04 的名字绑定来预测下面的例子。假设两个文件在同一目录，启动一个新进程运行 `app.py`。

`settings.py`

```python
print("加载 settings")  # ①
timeout = 30
```

`app.py`

```python
import settings
from settings import timeout

settings.timeout = 60

print(settings.timeout)  # ②
print(timeout)           # ③
```

先判断 ① 会执行几次，再写出 ② 和 ③ 的输出，并指出这两个表达式各自从哪里读取值。

① 执行一次。② 输出 `60`，因为它每次都通过模块对象读取属性。③ 输出 `30`，因为 `app.py` 中的 `timeout` 在导入时已绑定到整数 `30`。给 `settings.timeout` 重新赋值只改变模块中的那个绑定。

如果 `settings.py` 定义的是列表 `tags = ["base"]`，要区分修改对象和重新绑定。

```python
import settings
from settings import tags

settings.tags.append("debug")
print(tags)           # ① ['base', 'debug']

settings.tags = ["new"]
print(tags)           # ② ['base', 'debug']
print(settings.tags)  # ③ ['new']

tags.append("trace")
print(tags)           # ④ ['base', 'debug', 'trace']
print(settings.tags)  # ⑤ ['new']
```

`append` 修改共享的列表，所以①能看到新增元素。重新赋值后，`tags` 保留旧列表，模块属性指向新列表。从此通过其中一个名字修改列表，另一个列表不会随之变化。

## 2. 包、相对导入与 `-m`

```text
project/
└── demo/
    ├── __init__.py
    ├── settings.py
    └── app.py
```

`demo` 是普通包。它的 `__init__.py` 可以留空。课堂例子特意加了输出，用来观察初始化顺序。

```python
# demo/__init__.py
print("初始化 demo")  # ①

# demo/settings.py
print("加载 settings")  # ②
timeout = 30

# demo/app.py
from .settings import timeout

print(timeout)  # ③
```

`.settings` 表示当前包里的 `settings` 模块。从 `project/` 新开进程运行 `python -m demo.app`，会按 ①、②、③ 输出“初始化 demo”、“加载 settings”和 `30`。直接执行 `python demo/app.py` 时，脚本没有 `demo` 的包上下文，第一条相对导入就会抛出 `ImportError`。

## 3. 循环依赖为什么可能失败

Python 会在执行模块顶层代码前先登记模块对象，因此另一个模块可能看到还没初始化完的模块。

```python
# a.py
print("开始加载 a")  # ①
from b import value_b
value_a = "A"
print("a 加载完成")  # ②

# b.py
print("开始加载 b")  # ③
from a import value_a
value_b = "B"
print("b 加载完成")  # ④
```

在文件所在目录新开进程运行 `python -c "import a"`，先输出 ①，再输出 ③。`b` 从已登记的 `a` 导入 `value_a` 时，`a` 还没运行那条赋值，导入失败。可以把双方共用的定义移到 `shared.py`，让两个模块分别依赖它。

## 4. `src` 布局与搜索路径

```text
project/
└── src/
    └── demo/
        ├── __init__.py
        ├── settings.py
        └── app.py
```

`src` 是源码目录，包名仍是 `demo`。在未安装项目、未额外配置搜索路径的情况下，从 `project/` 执行 `python -m demo.app` 找不到包。从 `project/src/` 执行同一命令，可以从当前目录找到 `demo/`。已经配置好打包方式的项目可用 `pip install -e .` 安装到当前环境，继续在原位置编辑源码。

## 5. 主练习：把提示词格式化器拆成一个包

在 `python/p09_demo/src/prompt_demo/` 创建下面四个文件。

| 文件 | 要求 |
|---|---|
| `__init__.py` | 留空即可 |
| `settings.py` | 定义 `MAX_CHARS = 5` |
| `formatter.py` | 用 `from .settings import MAX_CHARS`，实现 `format_prompt(text)`，返回文本的前 `MAX_CHARS` 个字符 |
| `app.py` | 从包中的 `formatter` 导入 `format_prompt`，在 `main()` 中打印 `format_prompt("hello!")`，用 `if __name__ == "__main__"` 控制入口 |

进入 `python/p09_demo/src/` 后，`python3 -m prompt_demo.app` 应输出 `hello`。同一目录下执行 `python3 -c "import prompt_demo.app"` 应成功导入且不打印。项目暂用当前目录进行模块查找，练习无需安装。

练习的实际导入顺序是 `app` → `formatter` → `settings`。用 `-m` 运行时，`app` 的 `__name__` 是 `"__main__"`，入口判断会调用 `main()`。单独导入时，`__name__` 是 `"prompt_demo.app"`，应用可以加载函数供其他代码使用，这次不会执行 `main()`。两种路径均已在 `src/` 下复测。
