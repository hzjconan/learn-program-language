## 2. 普通属性：读取、赋值与修改对象

针对本例中没有 property、自定义属性访问的普通属性，读取 `a.limit` 时先查实例 `a`，没有再沿类及基类查找。不能简单把 Python 类体中的属性理解为 Java 的实例字段声明：这里 `tags` 和 `limit` 都保存在类对象上，初始化时不会自动为每个实例复制一份。

`a.limit = 3` 在实例上建立属性，遮蔽同名类属性；`Cleaner.limit = 20` 则更新类上的属性。于是四行输出是：

```text
['trim'] ['trim']
3 10
3 20
A:3 B:20
```

`a.tags.append("trim")` 没有对 `a.tags` 赋值。它先通过属性查找取得类上的列表，再调用列表方法修改该对象，`b.tags` 读到的是同一个列表。这延续了 P04 的「重新绑定与修改对象」区别。

在 `__init__` 中赋值可以让每个实例拥有自己的列表：

```python
class Cleaner:
    limit = 10

    def __init__(self, name):
        self.name = name
        self.tags = []

    def label(self):
        return f"{self.name}:{self.limit}"
```

每次初始化都执行一次 `[]`，创建新列表。`self` 是约定俗成的参数名，指向本次调用传入的实例；本例 `a.label()` 通过方法绑定自动传入 `a`，等价于 `Cleaner.label(a)`。方法内部的 `self.limit` 仍使用同样的属性查找规则。

## 4. 组合与继承

组合让对象保存并使用其他对象。例如处理器保存一个清洗器，把清洗工作交给它。这里将依赖通过初始化参数传入，调用者可以选择清洗器，也可以让多个处理器共享同一个清洗器。

```python
class StripCleaner:
    def clean(self, text):
        return text.strip()


class DocumentProcessor:
    def __init__(self, cleaner):
        self.cleaner = cleaner

    def process(self, text):
        return self.cleaner.clean(text)


cleaner = StripCleaner()
processor = DocumentProcessor(cleaner)
print(processor.process("  Hello  "))
```

调用链是 `processor.process(...)` → `self.cleaner` 取出清洗器 → 清洗器的 `clean(...)`。`process` 中的 `self` 指向处理器；进入 `clean` 后，该方法的 `self` 指向清洗器。参数赋值保存对象引用，不会复制对象。

继承则表达一种类型关系，例如 `class LowerStripCleaner(StripCleaner): ...`。子类可继承或覆盖基类方法，属性查找也会沿基类继续。`super()` 按方法解析顺序寻找后续实现；在这里的单继承例子中，可用它调用基类的清洗逻辑。

```python
class LowerStripCleaner(StripCleaner):
    def clean(self, text):
        return super().clean(text).lower()
```

处理器「使用清洗器」，适合组合；小写清洗器「是一种清洗器」，可以用继承表达。Python 的普通调用 `self.cleaner.clean(text)` 不强制要求对象继承某个基类，只要实际对象提供兼容的 `clean` 方法即可。这是后续理解鸭子类型与 Protocol 的基础。

课堂追踪题：预测组合示例的输出，指出两个方法内 `self` 的具体对象；再判断把传入对象替换为 `LowerStripCleaner()` 后是否需要修改 `DocumentProcessor`。

追踪题批改：原清洗器输出 `Hello`，`strip()` 不改变大小写。替换成 `LowerStripCleaner()` 后输出 `hello`，处理器无需修改。各方法的 `self` 指向各自调用所绑定的对象，而不是变量名本身。

## 6. 特殊方法：让对象参与通用操作

组合练习已通过。`self.steps = [*steps]` 创建新外层列表，步骤对象仍共享；符合本题只隔离列表增删的要求。

Python 通过特殊方法约定支持对象的通用操作。以一个完整的小例子说明：

```python
class Prefixer:
    def __init__(self, prefix):
        self.prefix = prefix

    def __call__(self, text):
        return self.prefix + text

    def __repr__(self):
        return f"Prefixer(prefix={self.prefix!r})"


prefixer = Prefixer("Q: ")
print(prefixer("hello"))  # Q: hello
print(repr(prefixer))    # Prefixer(prefix='Q: ')
```

`prefixer("hello")` 通过 `__call__` 让实例可调用，类本身的调用 `Prefixer(...)` 则用于创建实例。`repr(obj)` 使用 `__repr__` 返回便于调试的字符串；f-string 中的 `!r` 对值使用 repr，让字符串带引号。`__str__` 面向普通文本展示；未定义时通常回退到 repr。特殊方法的隐式调用一般从对象的类型查找，不宜把它理解为普通实例属性查找的简单替换。

`len(obj)` 使用 `__len__`，结果必须为非负整数。类应自行明确「长度」的含义，例如流水线的步骤数。若未定义 `__bool__` 而定义了 `__len__`，真假判断也会使用长度，零长度对象为假。

扩展练习：在 `Pipeline` 添加 `__len__`（步骤数）、`__call__(text)`（复用 process）、`__repr__`（如 `Pipeline(steps=2, processed=1)`）。调用和直接 process 都应每次只记录一条历史。预测空流水线的 `bool` 结果并解释；该对象仍能处理文本。

### 扩展练习中的注解纠错

用户使用了 `*args: any, **kwds: any` 和返回注解 `any`。小写 `any` 是内置函数，例如 `any([False, True])` 返回 `True`，不能用它表示「任意类型」。类型标注中的 `Any` 来自 `typing`，与该函数不同。普通 Python 执行不会自动根据注解检查参数与返回值，所以运行通过不代表类型标注正确。

当前流水线只接收一个文本参数，直接写出 `text` 参数并标注输入输出为 `str`，更清晰地表达契约；无需为这一固定接口使用通用参数转发。具体修订由用户完成。

空流水线 `bool(q)` 为 `False`，`q("Hello")` 仍返回 `Hello`：真假判断使用长度，可调用性由 `__call__` 支持，二者互不替代。

## 7. 鸭子类型、ABC 与 Protocol

现有 `Pipeline` 调用 `step.clean(text)`，没有要求步骤继承特定基类；实际对象提供兼容方法即可。这是鸭子类型。ABC 和 Protocol 可以进一步表达契约，但作用不同。

### ABC：显式继承与抽象方法

```python
from abc import ABC, abstractmethod


class CleanerBase(ABC):
    @abstractmethod
    def clean(self, text: str) -> str:
        raise NotImplementedError


class TrimCleaner(CleanerBase):
    def clean(self, text: str) -> str:
        return text.strip()
```

`@abstractmethod` 把方法标为抽象方法（装饰器机制留到 A03）。没有实现全部抽象方法的类仍可定义，但不能实例化。`TrimCleaner` 实现后可以实例化。约束来自 ABC 机制，而不是方法体中的 raise；单独写 `raise NotImplementedError` 只能在方法实际执行时失败。ABC 本身也不会验证覆盖方法的完整签名与返回类型。

### Protocol：按结构描述能力

```python
from typing import Protocol


class CleanerLike(Protocol):
    def clean(self, text: str) -> str:
        ...


class ExternalCleaner:
    def clean(self, text: str) -> str:
        return text.strip()


def apply_cleaner(cleaner: CleanerLike, text: str) -> str:
    return cleaner.clean(text)


result = apply_cleaner(ExternalCleaner(), "  Hi  ")
```

`...` 在协议中表示省略实现，描述需要的方法即可。`ExternalCleaner` 不必继承 `CleanerLike`，静态类型检查器按方法结构与签名判断兼容性。这类似 TS 的结构类型与 Go 的隐式接口满足。这里未运行静态类型检查器，不把运行成功说成静态检查通过。

类型注解不会自动在运行时拦截错误对象。普通 Protocol 也不能直接用来做 `isinstance` 检查；加 `@runtime_checkable` 后可以检查，但它不验证完整方法签名或返回类型。本节先理解静态契约与运行行为的区别，泛型等留到 A01。

参考：[ABC 官方文档](https://docs.python.org/3/library/abc.html)、[Protocol 官方文档](https://docs.python.org/3/library/typing.html#typing.Protocol)。

### 报错时机纠正

`class MissingCleaner(CleanerBase): pass` 定义成功，它仍是抽象类；执行 `MissingCleaner()` 才因未实现抽象方法而抛出 `TypeError`。这是运行时创建实例阶段的限制。

`apply_cleaner(123, " Hi ")` 若交给静态类型检查器，会被报告参数不兼容。直接用 Python 运行不会自动执行这种类型检查；可以进入函数体，随后读取 `cleaner.clean` 时因整数没有该属性而抛出 `AttributeError`。Python 也会将源码编译成字节码，但这一步通常不执行此类注解类型检查，不能把静态检查一概称为 Python 的「编译时报错」。

换场景复测：定义 `class Incomplete(CleanerBase): pass`，以及未继承任何基类的 `class WrongCleaner`，后者的 `clean(self, text: str) -> int` 返回 `len(text)`。分别判断：Incomplete 类能否定义、能否实例化；WrongCleaner 是否静态满足 CleanerLike；不运行类型检查器时 `apply_cleaner(WrongCleaner(), " Hi ")` 会返回什么或抛出什么。

完整复测代码：

```python
class Incomplete(CleanerBase):
    pass


class WrongCleaner:
    def clean(self, text: str) -> int:
        return len(text)


result = apply_cleaner(WrongCleaner(), " Hi ")
print(result)
```

`Incomplete` 可以定义，不能实例化。`WrongCleaner.clean` 返回 `int`，与协议要求的 `str` 不兼容，所以不满足静态契约。普通 Python 运行仍会完成调用并打印 `4`，字符串有首尾两个空格。返回注解不会把整数自动转换成字符串，也不会自动抛出类型错误。
