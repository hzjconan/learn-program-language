## 1. 第一段：到底是谁运行代码

`python3 script.py` 的过程：shell 根据 PATH 查找 python3 → 启动该解释器 → 执行脚本。

- 解释器：执行 Python 代码的程序，其版本影响语法和标准库能力。
- 第三方包：安装在某个环境中的代码，通常位于该环境的 site-packages。
- 虚拟环境：围绕一个基础解释器建立独立的包安装环境；不是虚拟机或容器，也不自动隔离文件和网络。
- uv：管理 Python、项目、依赖、环境并运行命令的工具；它本身不代替 Python 解释器。

可类比 Node 与项目依赖，但 Python 中多个解释器与各自安装环境的对应关系需要特别留意。

确认实际解释器：

```bash
python3 -c 'import sys; print(sys.executable); print(sys.version)'
```

`command -v python3` 看 shell 选择；`sys.executable` 看实际进程。检查虚拟环境还可以对比 `sys.prefix` 与 `sys.base_prefix`。

激活虚拟环境主要调整当前 shell 的 PATH 等变量。也可以直接运行 `.venv/bin/python`；通过 uv 管理项目时可使用 `uv run`，不要求先手动激活。

| 对象 | 职责 | 版本控制 |

| pyproject.toml | 项目元信息、Python 范围、直接依赖、工具配置 | 提交 |

## 4. 第三段：运行入口

- `python path/to/file.py`：执行给定脚本文件。
- `python -m package.module`：通过模块搜索找到模块，并作为程序执行。
- `python -m pip`：让这个 Python 执行它能找到的 pip 模块，避免裸 pip 指向另一环境；前提是该环境安装了 pip。
- `uv run ...`：在 uv 选择或管理的环境中运行命令，项目场景下联系项目配置理解。

导入路径和包上下文可能因运行方式不同而改变。P01 用最小例子观察，P09 再展开机制。

## 6. 课堂补充：实际环境与项目初始化

本机另有 Homebrew Python 3.12.14（arm64）。机器安装的解释器与 PATH 默认选择是两回事。用户依次执行：

```bash
uv python list --only-installed
uv venv --python /opt/homebrew/bin/python3.12
source .venv/bin/activate
command -v python3
deactivate
uv init --bare --name python-ai-learning --python 3.12
uv sync
uv run python -c 'import sys; print(sys.version); print(sys.executable)'
```

最初教师给出的 `uv init --bare --python 3.12` 因目录名 python 不能作为项目名而失败，后用 --name 显式指定项目名，目录保持 python/。

- sys.executable 是解释器文件路径；sys.prefix 是当前环境前缀；sys.base_prefix 是基础安装前缀，不是可执行文件。
- 标准 venv 中用 `sys.prefix != sys.base_prefix` 判断；不能搜索路径里是否包含 .venv，环境可以改名。
- 激活只影响当前 shell；独立终端不自动继承，从当前 shell 启动的子进程通常继承环境。绝对路径命令绕过 PATH 查找。
- requires-python = ">=3.12" 是兼容范围，不等于固定为 3.12，也不会修改 shell 的 python3。
- dependencies = [] 不妨碍使用标准库。uv sync 创建或同步环境，uv.lock 不会仅因存在就安装依赖。
- 当前项目无第三方依赖，Resolved 1 package 不代表安装了一个第三方库。

## 7. 导入、模块缓存与程序入口

导入会执行模块顶层代码。同一进程正常重复导入同名模块会复用 sys.modules 中的对象；新进程有独立缓存。

```python
def main():
    print("执行诊断")


if __name__ == "__main__":
    main()
```

| 方式 | 模块内 __name__ | 是否调用上述 main |
|---|---|---|
| python check_env.py | __main__ | 是 |
| python -m check_env | __main__ | 是 |
| import check_env | check_env | 否 |
| import check_env 后 check_env.main() | check_env | 显式调用时执行 |

main 是普通函数名，Python 不会自动调用。导入时仍执行 def 定义和 if 判断，只是不执行 main 的函数体。避免在顶层直接加载模型、启动训练等不必要副作用。
