## 1. 可迭代对象与迭代器：先认识操作

可迭代对象（iterable）能提供迭代器，例如 list。迭代器（iterator）负责逐个提供值，并记录当前取到哪里。可以把列表看作一组数据，把列表迭代器看作读取这些数据的游标；这是本节列表例子的直觉，不表示所有可迭代对象都预先存储完整数据。

- iter(obj)：取得 obj 的迭代器。
- next(it)：向迭代器索取下一项，推进读取进度。
- list(it)：持续从迭代器取值，收集成列表。

这些操作关注数据如何被逐个读取。不要把迭代器的读取进度与原列表的增删修改混为一谈。

## 3. 迭代器怎样表示结束

当没有下一项时，next(it) 抛出 StopIteration，而不是返回 None。None 本身也可以是数据元素，因此不能把它一概作为结束标志。

for 会获取迭代器、反复取下一项，并在 StopIteration 时正常结束。可用下面的结构理解普通 for 的核心机制：

```python
items = [10, 20, 30]
it = iter(items)

while True:
    try:
        item = next(it)
    except StopIteration:
        break
    print(item)
```

只把 next 放进 try，避免把循环体自己抛出的 StopIteration 误当作取值结束。其他异常不会自动作为正常结束处理。list(it) 也会取值直到迭代结束，并返回收集出的列表，零项就是 []。

迭代器本身也可迭代，iter(it) 返回它自己；不会创建一个从头读取的新游标。给同一迭代器起别名也不会复制进度。

## 4. yield：用函数编写迭代器

普通函数调用后执行函数体，直到返回或抛出异常。含 yield 的普通 def 定义的是生成器函数：调用它先返回一个生成器对象，此时不执行函数体。生成器对象是一种迭代器，可以交给 next、for 或 list 消费。

每次 next 都会开始或恢复函数体执行；遇到 yield value，把 value 作为这次取值的结果交出去，同时暂停。暂停时保留执行位置和局部变量，下次 next 从上次 yield 后继续。遇到 return 或执行到函数体末尾，则结束迭代，后续取值抛出 StopIteration。

与 JS 的 function* / yield 有相似之处，但 Python 用 def 中的 yield 定义生成器函数，next(g) 直接取得产出值，结束通过 StopIteration 表示。yield 产出一个值不代表整个函数结束；return 则结束当前生成器，不会把它后面的代码留待下次继续。

### 执行顺序预测：先推理，不运行

```python
    print("begin")
    yield 10
    print("between")
    yield 20
    print("end")


g = numbers()
print("ready")
print(next(g))
print("pause")
print(list(g))
print(list(g))
```

### 产出、打印与收集的区别

第一次 next(g) 返回 10 后，生成器停在 yield 10 处，尚未执行下一行。后续 print(list(g)) 要先计算参数 list(g)，再由外层 print 打印其返回值。list 会反复取值，因此这一段按以下顺序发生：

1. 恢复生成器，执行 print("between")，立即输出 between。
2. 执行 yield 20，把20交给 list 收集；yield 自身不打印。
3. list 为继续收集再取下一项，生成器执行 print("end")，立即输出 end，随后执行到底，结束迭代。
4. list 处理迭代结束，返回 [20]；外层 print 此时才输出 [20]。

因此 yield 20、print(20)、return 20 含义不同：分别是向消费者产出值并暂停、向标准输出写文本、结束当前函数或生成器。最后一次 list(g) 面对已经耗尽的生成器，正常返回 []；StopIteration 是内部结束信号，不会作为异常传到这里的调用者。

用户已修订完整输出为 ready、begin、10、pause、between、end、[20]、[]，每项独占一行，并正确解释 list 必须先消费到迭代结束，才能返回列表供外层 print 打印。修订通过，未运行。

## 5. 循环中的 yield 与按需执行

```python
def squares(values):
    for value in values:
        yield value * value


g = squares([2, 3, 4])
first = next(g)  # 4，停在第一次 yield
second = next(g)  # 恢复循环，读入3，产出9
```

yield 可以出现在循环内部。恢复后程序继续按控制流执行，直到下一个 yield 或结束；不是仅执行一行。调用者不再索取值时，生成器不会自行继续运行。因此，处理来源时不必预先计算全部结果；但若内部先写 list(values)，仍然会提前消费整个来源，不能只凭存在 yield 就认定实现按需读取。

## 6. 主练习：清洗文档并按批产出

骨架见 [a04_batches.py](../a04_batches.py)。实现 batched_docs(docs, batch_size)，使用 yield 逐批产出 list[str]：

- 对输入字符串 strip，跳过清洗后为空的文本，按有效文档数凑批。
- 满一批即产出，最后不足一批也产出；空输入或全空白输入不产出空批次。
- docs 可能是只能消费一次的迭代器，不整体转成列表，不提前收集全部输出批次。
- 每批是独立列表，不能让后续操作改变此前交出去的批次。
- 输入元素约定为 str，batch_size 约定为 int；batch_size <= 0 时抛出 ValueError。检查写在生成器函数体中，因此首次推进时执行，单纯创建生成器对象不会触发检查。

from collections.abc import Iterable, Iterator 用于标注：Iterable[str] 表示可迭代的字符串来源，既可传列表也可传迭代器；Iterator[list[str]] 表示逐项产出字符串列表的迭代器。这些标注本身不执行输入校验。

输入 iter(["  A ", "", " B", "   ", "C  "])、批大小2时，先取一批应得到 ["A", "B"]，再用 list 收集剩余批次得到 [["C"]]。不提前给出实现，用户完成后验证惰性读取和边界。

### 通过验证的完整实现

以下是用户完成并通过验证的实现，供独立复习：

```python
from collections.abc import Iterable, Iterator


def batched_docs(docs: Iterable[str], batch_size: int) -> Iterator[list[str]]:
    if batch_size <= 0:
        raise ValueError("batch_size 必须为正整数")

    batch: list[str] = []
    for doc in docs:
        cleaned = doc.strip()
        if not cleaned:
            continue
        batch.append(cleaned)
        if len(batch) == batch_size:
            yield batch
            batch = []
    if batch:
        yield batch


source = iter(["  A ", "", " B", "   ", "C  "])
batches = batched_docs(source, batch_size=2)
print(next(batches))  # ['A', 'B']
print(list(batches))  # [['C']]
```

yield 交出去的是列表对象的引用，不会复制列表。batch = [] 在恢复后把局部名字绑定到新列表，之前交出去的列表仍保留原内容。这与 P04 的对象和引用机制一致。

## 7. 最终复测：列表对象与执行时机

假设将实现中的 batch = [] 换成 batch.clear()，执行：

```python
g = batched_docs(["A", "B", "C", "D"], 2)
first = next(g)
second = next(g)

print(first)
print(second)
print(first is second)
```

输出依次是 ['C', 'D']、['C', 'D']、True。第一次产出后 first 保留列表引用；恢复时 clear 原地清空同一个列表，再追加C、D；第二次产出的仍是这个对象。局部名字重新绑定和原地修改是两种不同操作。用户全部预测正确，并解释了 clear 不创建新列表的原因。
