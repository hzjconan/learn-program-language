## 第一轮讲解：标注、执行与联合类型

### 1. 标注描述约定，执行由实际对象决定

题一中 a 为字符串 `"hello"`。调用 `title(123)` 时，Python 不会仅因 `text: str` 拒绝参数，也不会自动调用 str 转换它；进入函数后，text 绑定整数123，执行 `text.strip()` 时，因为整数没有 strip 属性而触发 AttributeError。异常发生在函数体的属性访问处。类型检查工具则可以在运行前报告调用处传入 int 不符合 str 参数约定。

题二普通执行可以到达 print，输出 `['python', 42]`。`list[str]` 表达「希望这个列表的元素都是字符串」，不会创建一个自动拦截整数的特殊列表。实际对象是普通 list，append 可以加入整数；类型检查工具应报告这次 append 不符合元素类型约定。

这与 TS 的一个相似点是，类型检查和实际执行需要分开看。Python 自身运行时也有类型：例如字符串和整数支持的操作不同，某个实际操作可能失败。只是函数或变量上的这些类型标注，默认不执行参数、返回值或容器内容校验。框架可以主动读取标注并校验数据，那是框架增加的行为。

### 2. 泛型写的是内部数据的类型

`list[str]` 描述元素为字符串的列表；`dict[str, str]` 描述键和值均为字符串的字典；`list[dict[str, str]]` 则是一个列表，每个元素是这样的字典。可以从外向内逐层阅读。

`dict[str, str]` 并没有表达「一定包含 id 和 text」，也没有限制只能使用这两个键。这类具体字段结构稍后由 TypedDict 表达。当前 find_text 例子仍假设所需键存在，若实际缺键，运行时可能出现 KeyError。

### 3. 联合类型与可能缺失的结果

题三没有匹配项时执行到函数末尾，隐式返回 None。因此 `-> str` 未完整描述实际返回行为，应写成 `-> str | None`。`|` 在这里表达联合类型，即结果可能是字符串，也可能是 None；它不会转换或校验结果。

一个不同场景的完整示例：

```python
def first_line(text: str) -> str | None:
    if text == "":
        return None
    return text.split("\n", 1)[0]


line = first_line("hello\nworld")
if line is None:
    print("没有内容")
else:
    print(line.upper())
```

函数对空字符串返回 None，否则最多切分一次并取第一段。调用者先检查 None，再使用字符串方法；类型检查工具也可以据此在 else 分支把 line 的可能类型缩小为 str，这称为类型收窄。函数末尾隐式返回 None 与显式 return None 的运行结果相同；这里显式写出缺失分支便于阅读。

`str | None` 可与 TS 的 `string | null` 作类比，但 Python 的 None 是独立的单例值，Python 中不存在 JS 的 undefined。检查是否为 None 用 `is None`，延续 P02 的约定。

不要无条件把 `is None` 改成真假判断：例如 `""` 是字符串但也是假值；「没有结果」和「结果是空字符串」可能是两种业务情况。

## 第二轮讲解：Literal 与 TypedDict

### 1. Literal 表达允许的具体值

str 表示字符串类型，不能区分任意字符串与业务允许的几个值。Literal 可以把范围缩小到具体值：

```python
from typing import Literal


def set_mode(mode: Literal["fast", "safe"]) -> None:
    print(mode)
```

静态检查允许 set_mode("fast")，应指出 set_mode("turbo") 不符合参数约定。普通执行后者仍能打印 turbo，因为这里没有编写运行时校验。Literal 不是枚举类，也不会创建新的字符串对象；传入的仍是普通 str。可类比 TS 的字符串字面量联合类型 `"fast" | "safe"`。

### 2. TypedDict 描述具体键与各自的值类型

dict[str, str] 描述键和值的类型，但不能表达某些键必需存在，也不能表达不同字段分别使用 int、str 等不同类型。TypedDict 用于描述这样的字典结构：

```python
from typing import Literal, TypedDict


class JobConfig(TypedDict):
    mode: Literal["fast", "safe"]
    retries: int


def describe_job(config: JobConfig) -> str:
    return f"{config['mode']}: retries={config['retries']}"


config: JobConfig = {"mode": "safe", "retries": 2}
print(describe_job(config))
```

该示例输出 safe: retries=2。默认情况下，TypedDict 中声明的字段均为必需字段；静态检查应报告缺少 retries、retries 类型错误、mode 不在允许值内等问题。此例使用字典字面量创建 config，实际对象仍是普通 dict，通过 config["mode"] 访问字段，不能写 config.mode。类形式在这里用于声明字典的类型结构，不意味着 config 成为拥有实例字段的 JobConfig 对象。

TypedDict 不会自动验证 JSON 或其他输入。把不合契约的字典赋给带标注变量，普通执行不会单凭标注拒绝赋值；后续访问缺失键仍可能发生 KeyError。静态契约有助于检查代码，但不代替数据入口校验，后者在 A02 学习。

字段值允许 None 与字段可以省略是两个不同概念：例如 retries: int | None 默认仍要求有 retries 键，只是允许其值为 None。可省略字段的标注稍后按需展开。

## 综合练习评审：逆序查找与真假值

用户用 reversed、生成器表达式和 next 实现查找，原脚本与独立验证均通过。表达式可拆成三部分：

```python
next((msg for msg in reversed(messages) if msg["role"] == "user"), None)
```

1. reversed(messages) 从列表末尾向前遍历，不会原地改变列表顺序。它不同于 messages.reverse()，后者会修改列表。
2. `(msg for ... if ...)` 是生成器表达式，按需提供匹配的消息字典；不同于列表推导式，不在此处预先构造完整结果列表。生成器机制在 A04 系统展开。
3. next(..., None) 获取第一个匹配字典；没有匹配项则返回默认值 None。因为遍历是逆序，第一个匹配项就是原顺序中的最后一条 user 消息。

用户先取得 Message 字典，再判断它的真假值。合法 Message 必含 role 与 content，因此即使 content 为空字符串，字典自身仍非空，是真值；随后读取 content 会正确返回空字符串。若改为先取字符串再使用真假判断，空字符串就可能被误判为没有结果。使用 is not None 可以更明确表达缺失检查。

代码可读性：局部变量应以保存的对象命名，例如 last_message；不宜与 find_last_user_text 函数同名。同名赋值在本次调用中是局部绑定，不会覆盖模块级函数，但会遮蔽函数体内该名字。删除未使用的 pickletools.read_uint2 导入。

## 最终示例与收尾纠错

用户已完成清理并通过收尾理解题。下面收录用户最终实现的核心代码，供独立复习；完整用户断言保留在 [a01_message.py](../a01_message.py)。

```python
from typing import Literal, TypedDict


class Message(TypedDict):
    role: Literal["user", "assistant"]
    content: str


def make_message(role: Literal["user", "assistant"], content: str) -> Message:
    return {"role": role, "content": content}


def find_last_user_text(messages: list[Message]) -> str | None:
    last_message = next(
        (msg for msg in reversed(messages) if msg["role"] == "user"),
        None,
    )
    return last_message["content"] if last_message else None
```

此处返回前检查的是 last_message，它为必含两个键的 Message 字典或 None，因此保留空字符串。若生成器直接返回 content，得到的是 str | None，则 `return text if text else None` 会将空字符串错误变成 None。需区分缺失值时，可以显式检查 `text is not None`；如果只是原样传回 str | None，直接 return text 即可，无需条件表达式。
