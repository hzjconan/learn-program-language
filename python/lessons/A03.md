## 1. 先还原 @ 语法

函数可以作为参数传入另一个函数，也可以作为返回值返回。把这件事用于函数定义，就得到一种常见的装饰器写法：

```python
@decorate
def work():
    ...
```

对于这个简单例子，可以按下面理解：

```python
def work():
    ...

work = decorate(work)
```

执行到定义处时，先创建原函数对象，再调用 decorate，把原函数对象作为参数传入；返回结果绑定到 work 名字。没有写 work()，不代表没有执行 decorate。以后调用 work() 时，调用的是这个名字当前指向的对象。

装饰器可能返回一个包装函数，也可能保留原函数。例如 @dataclass 的作用对象是类，不能据 @ 就推断一定创建了函数包装器。本节先用包装函数把调用过程看清楚。

## 3. 通用参数与返回值转发

原例的 wrapper(name) 只适配单个 name 参数。为了包装参数形式不同的普通同步函数，可以接收并转发位置参数与关键字参数：

```python
def announce(fn):
    def wrapper(*args, **kwargs):
        print("before")
        return fn(*args, **kwargs)

    return wrapper
```

定义中的 *args 将位置参数收集成 tuple，**kwargs 将关键字参数收集成 dict；调用 fn 时的 *args 和 **kwargs 则分别解包。比如 wrapper("Ada", loud=True) 会收集 args == ("Ada",)、kwargs == {"loud": True}，再转发成 fn("Ada", loud=True)。原函数继续负责自己的参数绑定和检查。

这里有两个不同的 return：外层 return wrapper 在装饰时交出包装函数；内层 return fn(...) 在调用时把原函数的结果交给调用者。如果内层只调用 fn(...) 而不 return，原函数仍会执行，但 wrapper 正常执行到底会返回 None。

### 读错题：先推理，不运行

```python
def trace(fn):
    def wrapper(*args, **kwargs):
        print("call")
        fn(args, kwargs)
    return wrapper


@trace
def total(a, b, *, tax=0):
    return (a + b) * (1 + tax)


print(total(10, 20, tax=0.1))
```

问题：进入 wrapper 时 args 和 kwargs 分别是什么？fn(args, kwargs) 实际给原函数传了什么？原样执行会输出什么、是否报错？只修正参数转发后最外层 print 会打印什么？最后修正 wrapper，让结果能传回调用者。

批改说明：args 是 (10, 20)，kwargs 是 {"tax": 0.1}。错误调用将整个元组传给 a、整个字典传给 b，tax 因未按关键字传入而使用默认值 0；先打印 call，再因元组与字典不能相加而抛出 TypeError。修正为 fn(*args, **kwargs) 只解决参数转发；还须加 return，才能把原函数的结果交回调用者。用户已自行修正为 return fn(*args, **kwargs)。

## 4. 包装后的函数信息与 functools.wraps

函数也是对象，带有可读取的属性。例如 __name__ 是函数名字，__doc__ 是函数的文档字符串。在前面的包装中，greet 指向 wrapper，所以默认读取到的是 wrapper 的属性；重新绑定名字不会自动复制原函数的信息。

```python
from functools import wraps


def trace(fn):
    @wraps(fn)
    def wrapper(*args, **kwargs):
        print("call")
        return fn(*args, **kwargs)
    return wrapper


@trace
def greet(name: str) -> str:
    """生成问候语。"""
    return f"hello {name}"
```

@wraps(fn) 用原函数的信息更新包装函数，包括这里关注的 __name__、__doc__ 和 __annotations__，并设置 __wrapped__ 指向被包装的原函数。它不会把 greet 重新绑定回原函数，也不会替我们转发参数或返回值；实际调用依然进入 wrapper。

这有助于日志、帮助信息和后续工具注册读取原函数的名字与说明。__wrapped__ 还为后面读取函数签名提供了追溯原函数的入口。

预测题（先推理不运行）：以上代码随后执行 print(greet.__name__)、print(greet.__doc__)、print(greet("Ada"))，输出哪些行？如果只删除 @wraps(fn)，greet.__name__ 又是什么？

预测结果为 greet、生成问候语。、call、hello Ada，每项独占一行。删除 wraps 后，__name__ 是 wrapper。__name__ 属性和变量名是两件事：变量 greet 指向包装函数，并不会自动把包装函数的 __name__ 改为 greet。读取 greet.__annotations__ 可以取得原函数被保留下来的参数及返回值类型信息；本例没有启用延迟注解，包含 name 对应 str、return 对应 str。这些信息供程序读取，不负责校验参数值。

## 5. 函数签名与参数绑定

```python
import inspect


def search(query: str, *, limit: int = 5) -> list[str]:
    """搜索文档。"""
    return [query] * limit


print(inspect.signature(search))
# (query: str, *, limit: int = 5) -> list[str]
```

签名包含参数名字、顺序、传参方式、默认值和注解。单独的 * 表示后面的 limit 是关键字专用参数。注解描述标注的类型，不包含默认值与传参方式，也不会自动执行运行时类型检查。

若用上一节带 wraps 的 trace 装饰 search，inspect.signature(search) 默认沿 __wrapped__ 展示原函数的签名；包装函数的实际参数定义仍是 *args、**kwargs。

search("python", 2) 能进入 wrapper，先打印 call；转发给原函数时，因原函数只允许一个位置参数而抛出 TypeError。search("python", limit=2) 则打印 call，并返回 ["python", "python"]。用户对这三项预测均正确，尚未运行。

## 6. 工具注册：装饰器也可以返回原函数

注册表是保存“工具名 → 函数对象”的字典。装饰时把函数放进字典，调用时再根据名字查出函数并执行。存函数对象不会运行函数；存调用结果则会在注册时执行，语义不同。

注册装饰器可以完成登记后直接返回原函数，不需要 wrapper。由于没有创建包装函数，这个场景也不需要 wraps。装饰器的返回值仍会绑定回定义处的函数名，因此必须考虑直接调用是否还能工作。

练习骨架在 [a03_tools.py](../a03_tools.py)。实现 register(fn)：以 fn.__name__ 为键存入 TOOLS，重复名字抛出 ValueError，返回原函数。实现 describe_tool(name)：读取注册的函数，返回 name、description、signature 三个字段，后两者分别使用 __doc__ 和 str(inspect.signature(...))；未知名字允许 KeyError 传播。不要在注册时调用工具。

## 7. 换场景复测：登记成功不代表名字绑定正确

```python
TOOLS = {}


def register(fn):
    TOOLS[fn.__name__] = fn
    # 故意漏掉 return fn


@register
def double(x):
    return x * 2


print(double)
print(TOOLS["double"](3))
print(double(3))
```

前两行依次输出 None 和 6，最后一行抛出 TypeError。登记时字典保存了原函数对象；register 执行到底隐式返回 None，装饰语法把这个返回值绑定给 double。字典中的引用不会因 double 的重新绑定而消失。这也解释了为什么装饰器返回值必须与后续调用方式一致。用户先推理作答，结果和原因均正确。
