# Python 教学约定

## 范围与目标

- 所有课程资料和练习放在本目录，避免修改 Go 课程或外部参考项目。
- 以 `LEARNING-PLAN.md` 为课程依据，以 `NOTES.md` 为唯一当前进度入口；更新进度时同步对应课程记录。
- 用户有 JS/TS、Java、Go 编程经验，Python 和 PyTorch 需要系统学习。用旧语言辅助理解，但讲清 Python 自身的机制。
- 实际训练参考项目 `../..` 之外的 `/Users/hzjconan/workspace/tu-assistant` 使用 MLX/MLX-LM，不要误称为 PyTorch 项目。

## 教学节奏

- 每节 1～2 小时，包含讲解、理解题、用户编码、评审和修订；复杂内容拆节。
- 讲解 → 出题 → 用户写 → 评审 → 用户修订 → 换场景复测。不要直接替用户完成学习任务或提前给完整答案；用户明确要求时除外。
- 预测题先推理再运行；同时练习写代码、读代码找错、解释原因。
- 已学知识先摸底；熟练内容缩短，有疑问再展开。后续场景要回访旧知识和错题。
- 前期可提供必要测试骨架，逐步让用户补边界、独立写测试和暴露错误。
- 讲义按需准备，笔记区分用户原答案与教师批改；不要替用户编造心得或完成记录。
- QA 攒几条后与用户确认再沉淀，不把所有即时问答自动写入手册。
- 每节课结束，主动补齐讲义、原答案与批改、练习验证、错题和当前进度；不得只保留在对话中。
- 落文档后先向用户说明本节结果和待提交范围，得到用户确认后再 git commit 和 git push；结束一节课本身不代表获得提交推送授权。
- 提交仅包含本课程相关内容，不混入 Go 或其他任务的改动，不提交虚拟环境、字节码或缓存。

## 实验与参考项目

- 必修实验提供 M1 Pro / 32GB 本机可运行版本；PyTorch 用 CPU/MPS，实际项目用 MLX。
- 先做短实验测量耗时和内存，再扩大规模；课堂尽量几分钟内反馈，长训练为课间选做。
- 不假设 CUDA 实现能在 MPS 运行，也不假设 MLX 的量化训练方案能直接迁移到 PyTorch。
- 不自动租 GPU、启动长训练或修改参考项目。相关操作按实际任务授权和目录权限执行。
- 读取外部项目前遵守其 AGENTS.md；尤其不得读取 tu-assistant 的 inputs/ 材料。
- 实施时核对工具版本、官方文档与实际环境；既有项目文档中的诊断也需要区分观察、假设和验证结论。
