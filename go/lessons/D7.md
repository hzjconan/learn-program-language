## 0. 本周复盘

### 0.1 结清遗留问题：切片怎么知道起始位

D3 你问的：**「有了指向底层数组的指针和 len，它怎么知道起始位是多少？」**

答案是：**指针本身就是起始位。** 实测：

```
数组 arr 首元素地址 = 0x...040，每个 int 占 8 字节

arr[:]       ptr=0x...040  len=8 cap=8
arr[2:5]     ptr=0x...050  len=3 cap=6    ← 040 + 16 = 跳过 2 个 int
arr[4:]      ptr=0x...060  len=4 cap=4    ← 040 + 32 = 跳过 4 个
arr[6:7]     ptr=0x...070  len=1 cap=2    ← 040 + 48 = 跳过 6 个
```

切片头里的 `ptr` 指向**「这个切片的第 0 个元素」**，不是「底层数组的第 0 个元素」。`s[2:5]` 编译出来就是把指针往后挪 `2 × 元素大小`。

三条推论：

- **切片根本不知道底层数组从哪儿开始**，也不需要知道
- **`cap` 是「从 `ptr` 到底层数组末尾还剩多少个元素」**——所以 `arr[2:5]` 的 cap 是 6（下标 2 到 7），不是 8
- **切片没法往前扩**，它手上只有「我的起点」和「往后还有多少」

> 这也解释了 D3 那个别名问题的本质：**两个切片共享底层数组，是因为它们的 `ptr` 落在同一块内存里**——不管它们的起点差多少。

### 0.3 你这周答错过的五条（会在第 21 天重测）

1. **值接收者与调用者无关**——`p.Inc()` 展开成 `(*p).Inc()`，先解引用再整个拷贝
2. **可寻址 vs 方法集是两条规则**——可寻址时编译器帮你取地址；接口赋值只认方法集，不帮忙
3. **type switch 从上往下匹配**——接口 case 放前面会吃掉后面的具体类型 case
4. **`comparable` 挡不住装了 slice 的 `any`**——编译期放行，运行时 panic
5. **泛型 vs 接口**——`[]T` 是同质的，`[]Payer` 是异质的；要「一堆不同类型放一起」只能用接口

## 1. 项目：`loganalyze`

一个命令行日志分析工具：**读日志 → 解析 → 聚合统计 → 多格式输出**。

```
go/internal/logx/          ← 主要代码在这儿
├── logx.go                ← 类型与解析（D1 D2 D3）
├── report.go              ← 聚合统计（D3 D4）
├── format.go              ← 可插拔输出（D5）
├── *_test.go              ← 我写好的测试，别改
└── testdata/sample.log    ← 样本数据
go/cmd/loganalyze/         ← 薄薄的 main（D6 §11）
```

### 1.1 日志格式

每行五个部分，**空格分隔，消息是剩下的全部**：

```
2026-08-18T10:23:45Z INFO api-gateway 15 GET /users/42 -> 200
│                    │    │           │  │
│                    │    │           │  └ 消息（本行剩下的全部，可含空格，也可以为空）
│                    │    │           └─── 耗时，毫秒（非负整数）
│                    │    └─────────────── 服务名（非空、不含空格）
│                    └──────────────────── 级别（DEBUG/INFO/WARN/ERROR，大小写不敏感）
└───────────────────────────────────────── 时间（RFC3339）
```

- **时间**：RFC3339（`time.RFC3339`）
- **级别**：`DEBUG` / `INFO` / `WARN` / `ERROR`，大小写不敏感
- **服务名**：任意非空字符串，不含空格
- **耗时**：整数毫秒，非负
- **消息**：这一行剩下的全部内容，**可以含空格，也可以为空**

### 1.2 要实现什么

按依赖顺序分四步，**每步做完先让对应的测试变绿再往下走**。

**① 类型与解析**（`logx.go`）

- `Level` 具名类型 + `iota` + `String()` + `ParseLevel()`（D1）
- `Entry` struct（D4）
- `ParseError` 带**行号**和**字段名**，支持 `errors.As` 和 `Unwrap`（D2）
- `ParseLine(line string) (Entry, error)`

**② 聚合**（`report.go`）

- `Report` 累积统计：总行数、按级别计数、按服务计数、耗时分位数、最慢的 N 条
- `Percentile(p float64)`：`p=0.95` 返回 p95
- `TopSlowest(n int)`：按耗时降序，**耗时相同时按时间升序**（保证确定性）

**③ 流式分析**（`report.go`）

- `Analyze(r io.Reader) (*Report, error)`
- 参数是 `io.Reader` 不是文件名——**这是 D5 §2 的小接口哲学**，测试才能用 `strings.Reader`
- **单行解析失败不中断**：记进 `Report.Failed`，继续下一行

**④ 可插拔输出**（`format.go`）

- `Formatter` 接口：`Format(w io.Writer, r *Report) error`
- `TextFormatter`：人看的表格
- `JSONFormatter`：机器读的
- **`Analyze` 和 `Report` 里不能出现任何一个 `fmt.Print`**——输出全部经由 `io.Writer`

**⑤ CLI**（`cmd/loganalyze/main.go`）

```bash
go run ./cmd/loganalyze -format=text internal/logx/testdata/sample.log
go run ./cmd/loganalyze -format=json -top=5 internal/logx/testdata/sample.log
cat access.log | go run ./cmd/loganalyze          # 不给文件名就读 stdin
```

`main` 要薄：解析 flag、打开文件、调 `logx`、把错误打到 stderr 并 `os.Exit(1)`。**逻辑一行都不要写在 main 里。**
