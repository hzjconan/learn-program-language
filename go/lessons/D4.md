## 1. struct 基础

### 定义与字面量

```go
type User struct {
	Name string
	Age  int
}

u1 := User{Name: "Alice", Age: 30}   // ⭐ 具名字段，永远用这个
u2 := User{"Alice", 30}              // 位置字面量，脆弱
u3 := User{}                          // 零值：Name="" Age=0
u4 := &User{Name: "Alice"}            // 取地址，最常见的一行（D2 §2.4）
var u5 User                           // 同 u3
```

**永远用具名字段。** 位置字面量在别人给 struct 加字段、调字段顺序时会静默出错（或编译失败）。`go vet` 对**跨包**的位置字面量会报警，同包内不管——所以靠自觉。

### 零值可用

回到 D1 §3 那条哲学：**好的 struct，零值就应该能用。**

```go
var buf bytes.Buffer   // 直接 buf.WriteString(...)
var mu sync.Mutex      // 直接 mu.Lock()
var wg sync.WaitGroup
```

设计自己的类型时往这个方向靠：能不需要初始化就不需要。这是 Go 不需要构造函数的前提。

### struct 可比较，但有条件

```
Point{1,2} == Point{1,2} → true      ← 逐字段比较
```

**所有字段都可比较，这个 struct 才可比较。** slice / map / func 不可比较，会**传染**给包含它们的 struct：

```go
type WithSlice struct{ Tags []string }
w1 == w2    // ❌ 编译错误
```

可比较的 struct 能当 map 的 key，这是个很有用的性质（比如 `map[Point]bool`）。

### 拷贝是浅拷贝

```
w2 := w1 后改 w2：w1.Name="a"（独立） w1.Tags=[改了]（串了）
```

D2 §2.5.1 讲过，这里再确认一次：**值字段独立，slice/map/指针字段仍然共享底层数据。**

### 匿名 struct

一次性的数据形状，不值得起名字：

```go
tests := []struct {
	name string
	in   int
	want string
}{ ... }              // ← 你每天写的表驱动测试就是它
```

## 2. 方法

```go
func (u User) Greet() string { return "你好，" + u.Name }
//    ^^^^^^^ 接收者（receiver）
```

**方法就是「第一个参数写在前面」的函数。** 没有 `this`、没有 `self`——接收者的名字由你起，惯例是**类型名的首字母小写**（`u User`、`c *Counter`），而且**同一个类型的所有方法要用同一个名字**。

三条规则：

1. **只能给「本包内定义的类型」加方法。** 不能给 `int`、`time.Time`、别人包里的类型加方法。想扩展？定义一个自己的类型：`type MyInt int`。
2. **接收者可以是任何类型，不只是 struct**：`type Celsius float64` 也能有方法（D1 那个练习本来可以加 `String()`）。
3. **方法和字段共享命名空间**：一个 struct 不能同时有字段 `Name` 和方法 `Name()`。

> 对比 Java：Java 的方法是「类的一部分」，写在 `class {}` 里面；**Go 的方法是独立的顶层声明**，可以分散在包内任意文件。这个差别在读大型 Go 项目时很明显——一个类型的方法可能散落在五个文件里。

## 3. 值接收者 vs 指针接收者 —— 今天最实用的一节

### 基本差别

```
调用 3 次 IncVal（值接收者）后... c.N = 0   ← 一次都没生效
调用 3 次 IncPtr（指针接收者）后... c.N = 3
```

**值接收者拿到的是一份拷贝**（D2 §2.5：Go 永远传值），改它等于白改。

> **这个 bug 有工具兜底**：我写演示时 `golangci-lint` 当场报了
> `SA4005: ineffective assignment to field Counter.N`。
> 只要你跑 `make check`，这类错误抓得住。

### 编译器会自动取地址

```go
c := Counter{}    // c 是【值】，不是指针
c.IncPtr()        // ✅ 能调！编译器改写成 (&c).IncPtr()
```

反过来也成立：`p.ValMethod()` 会被改写成 `(*p).ValMethod()`。

**前提是「可寻址」**（D2 §2.1.3）。所以这个不行：

```go
m := map[string]Counter{}
m["k"].IncPtr()    // ❌ map 元素不可寻址
```

### ⚠️ 方法集：接口赋值时【不会】自动取地址

这是今天最容易踩的坑：

```go
type Greeter interface{ Greet() string }

func (p *PtrGreeter) Greet() string { ... }   // 指针接收者

var g Greeter = &PtrGreeter{}   // ✅
var g Greeter = PtrGreeter{}    // ❌ 编译错误：
                                //   PtrGreeter does not implement Greeter
                                //   (method Greet has pointer receiver)
```

**规则：**

| 类型 | 方法集包含 |
|---|---|
| `T` | 只有**值接收者**方法 |
| `*T` | 值接收者 **+** 指针接收者方法 |

**为什么直接调用可以、接口赋值不行？**

直接调用时编译器**看得见**那个变量，知道它可不可寻址，能帮你取地址。而赋值给接口时，接口里存的是一份**值的拷贝**——对这份匿名的临时拷贝取地址没有意义（你改了它，原对象也不会变）。所以 Go 干脆禁止。

**实践推论：如果一个类型有任何指针接收者方法，就总是用 `*T` 去满足接口。** 你会看到 Go 代码里大量的 `&Foo{}`，原因就在这。

### 怎么选

| 用指针接收者 | 用值接收者 |
|---|---|
| **需要修改接收者** | 只读 |
| struct 较大，拷贝成本高 | 小 struct（几个字段） |
| 类型含 `sync.Mutex` 等**不可拷贝**的字段 | —— |
| 需要 nil 接收者有意义（少见） | 类型本身就是小值语义（`time.Time`、`Celsius`） |

### ⭐ 一致性规则：别混用

> **一个类型的方法，要么全用值接收者，要么全用指针接收者。**

这是 [Go Code Review Comments](https://go.dev/wiki/CodeReviewComments#receiver-type) 的明确建议，理由：

1. 混用时，`T` 和 `*T` 的方法集不同，谁能满足接口全靠记忆
2. 读者无法预期哪个方法会改对象

**只要有一个方法需要指针接收者，就把所有方法都改成指针接收者。**

### 特例：错误类型几乎总用指针接收者

D2 §4 埋的伏笔在这里揭开：

```go
func (e *ParseError) Error() string { ... }
```

因为 `errors.Is` 比较的是**接口相等**（QA #8）。值接收者意味着「字段相同即相等」——第 3 行和第 3 行的两个不同解析失败会被认为是同一个错误。**指针给你身份语义，值给你相等语义。**

反例：`CodeError{404}` 这种纯粹的「分类标签」，值接收者才是对的。

## 4. 嵌入 ≠ 继承 —— 今天的题眼

### 什么是嵌入

```go
type Child struct {
	Base        // ← 只写类型名，不写字段名，这就是「嵌入字段」
	Age int
}
```

内层的**字段和方法都会被提升**到外层：

```
c.Label() = 我是 阿狗       ← Base 的方法
c.Name    = 阿狗            ← Base 的字段
c.Base.Name = 阿狗          ← 展开写也行
```

**但这只是语法糖。** 编译器把 `c.Label()` 改写成 `c.Base.Label()`，仅此而已。

### ⚠️ 没有多态覆盖

看这段「Java 味」的代码：

```go
type Animal struct{ Name string }
func (a Animal) Speak() string { return a.Name + "说：" + a.Sound() }  // 模板方法
func (a Animal) Sound() string { return "……（没有声音）" }               // 想被覆盖

type Dog struct{ Animal }
func (d Dog) Sound() string { return "汪！" }    // 看起来像覆盖
```

```
d.Sound()  = 汪！                        ← 直接调，用的是 Dog 的
d.Speak()  = 阿黄说：……（没有声音）        ← ⚠️ 调到的是 Animal.Sound！
```

**在 Java 里这段代码会输出「阿黄说：汪！」。Go 里不会。**

**原因**：`Speak` 的接收者 `a` 的静态类型就是 `Animal`。它**根本不知道自己被嵌进了 `Dog` 里**——嵌入是外层单方面的事，内层毫不知情。没有虚函数表，没有动态派发，`a.Sound()` 在编译期就绑死到 `Animal.Sound` 了。

> **一句话：Go 的嵌入是「has-a 的语法糖」，不是「is-a」。**
> 它给你代码复用，不给你多态。

这条直接毙掉一大批 Java 设计模式：**模板方法、抽象基类、受保护的钩子方法**——在 Go 里全部失效。

### 正确做法：把「可变的部分」抽成接口

```go
type Sounder interface{ Sound() string }

func SpeakVia(name string, s Sounder) string { return name + "说：" + s.Sound() }
```

```
阿黄说：汪！
咪咪说：喵~
```

**多态在 Go 里靠接口，不靠嵌入。** 而且注意：`Dog2` 里没有任何 `implements Sounder` 的字样——**接口是隐式实现的**，D5 细讲。

模式上的对应关系：

| Java | Go |
|---|---|
| 抽象基类 + 抽象方法 | **接口** |
| 模板方法（基类调子类） | **普通函数 + 接口参数** |
| 继承复用实现 | **嵌入**（纯复用，不含多态） |
| `super.method()` | `c.Base.Method()`（显式） |

### 名字冲突：深度优先，同深度必须显式

```
b.A.Who() = A
b.B.Who() = B
b.Who()   → 编译错误：ambiguous selector b.Who     （A、B 同深度，都有 Who）

o.Who()   = Outer（遮蔽了 A）    ← 外层深度更浅，赢
o.A.Who() = A                    ← 内层还在，只是要显式访问
```

**规则：深度浅的赢；同深度冲突则该名字「消失」**，必须显式写出路径。注意冲突不是编译错误，**只有你去用那个有歧义的名字时才报错**。

### 嵌入也能嵌接口

```go
type ReadWriter interface {
	io.Reader     // 嵌入接口
	io.Writer
}

type LoggingStore struct {
	Store         // 嵌入接口类型的字段！
	logger *slog.Logger
}
```

第二种写法很有用：`LoggingStore` 自动获得 `Store` 的所有方法，你只需要**重新定义想拦截的那几个**。这是 Go 版的「装饰器模式」，D15 做测试打桩时会用。

## 5. 构造：没有构造函数

Go 没有 constructor。惯例是**返回值（或指针）的普通函数**：

```go
func NewUser(name string) *User {
	return &User{Name: name}
}
```

命名规范：

- 包里只有一个主要类型 → `New()`：`errors.New()`、`bytes.NewBuffer()`
- 多个类型 → `NewXxx()`：`http.NewRequest()`
- **优先让零值可用，能不写构造函数就不写**

### 需要很多可选参数怎么办

Java 用 Builder，Go 有两个选择：

**① 配置 struct（简单场景）**

```go
type ServerOption struct {
	Port    int
	Timeout time.Duration
}

func NewServer(opt ServerOption) *Server { ... }
NewServer(ServerOption{Port: 8080})     // 没填的字段取零值
```

**② 功能选项模式（Functional Options，库作者的标准答案）**

```go
type Option func(*Server)

func WithPort(p int) Option    { return func(s *Server) { s.Port = p } }
func WithTimeout(d time.Duration) Option { return func(s *Server) { s.Timeout = d } }

func NewServer(opts ...Option) *Server {
	s := &Server{Port: 80, Timeout: 30 * time.Second}   // 默认值
	for _, opt := range opts {
		opt(s)
	}
	return s
}

NewServer(WithPort(8080))
```

优点：加新选项不破坏现有调用方、默认值集中在一处、选项名自带文档。**代价是样板代码多**——只在写给别人用的库时才值得，内部代码用配置 struct 就够了。
